## Working title

AIZOYA Keyboard Journeys — final name pending.

## One sentence

Inspect how a task completes with a mouse and a keyboard, replay the recorded actions, and turn a successful route into a regression-test draft.

## Problem

A task can work with a mouse while a keyboard attempt gets stuck. Engineers need enough evidence to understand the attempted route, inspect focus and observed outcomes, reproduce the behavior and check a correction. A bounded failed attempt should invite review rather than be presented as a universal accessibility verdict.

## Current product

Our prototype runs mouse and keyboard routes in separate browser contexts against an owned practice store. The keyboard executor accepts a constrained set of key presses. A deterministic receipt checks task completion independently of the planner. Users can inspect captured frames and actions, replay saved actions in fresh contexts and export a fixed-template Playwright test draft.

Six authored cases cover an unfocusable control, corrected buttons, arrow-key radios, reordered controls, Space activation and a focus trap. A separately labelled gallery preserves actual scripted browser recordings with their source run and content hashes. Its standalone preview opens without a server or API key.
